# Project 项目选项菜单设计

## 背景

项目行目前同时显示“添加会话”“用 VS Code 打开目录”和“用资源管理器打开目录”三个图标按钮。它们占用较多横向空间，在窄侧边栏和最小窗口下尤其拥挤。本次将这三个操作折叠到一个项目选项菜单中，并使用用户提供的纵向三点图标作为统一入口。

## 目标

- 每个项目行只显示一个“项目选项”按钮。
- 选项菜单收纳且仅收纳以下三个现有操作：
  - 添加会话
  - 用 VS Code 打开目录
  - 用资源管理器打开目录
- 保留三个操作现有的业务行为、禁用规则和提示。
- 菜单可通过鼠标和键盘完整操作，并能可靠关闭和恢复焦点。
- 菜单在 light/dark 主题及最小窗口尺寸下均正确显示。

## 非目标

- 不新增、删除或重命名项目操作。
- 不改变项目激活、展开/折叠或拖拽排序逻辑。
- 不抽取全局通用菜单系统。
- 不改变主进程打开目录或启动 VS Code 的实现。

## 方案

采用 `ProjectSidebar` 内的受控弹出菜单。组件记录当前打开菜单对应的项目 ID，同一时间最多打开一个菜单。与原生 `<details>` 相比，该方案能明确控制点击外部关闭、键盘导航、焦点恢复和跨项目切换；与抽取通用菜单组件相比，本次改动范围更小，也不会为单一使用场景提前增加抽象。

## 组件与状态

### 项目选项按钮

- 将项目行现有三个独立操作按钮替换为一个按钮。
- 按钮使用复制到渲染进程资源目录的 `options.svg`。
- 按钮提供“项目选项”可访问名称，并设置 `aria-haspopup="menu"` 与反映实际状态的 `aria-expanded`。
- 点击关闭状态的按钮时打开该项目的菜单；再次点击同一按钮时关闭菜单；点击其他项目的按钮时切换到对应项目菜单。
- 按钮及其菜单区域继续阻止点击和指针事件触发项目激活、展开/折叠或拖拽。

### 选项菜单

- 菜单显示在对应项目行下方，与选项按钮右侧对齐并向左延伸；菜单受侧边栏可用宽度约束，不能超出可视区域。
- 菜单使用纵向紧凑布局，按以下顺序显示带文字和现有图标的菜单项：
  1. 添加会话
  2. 用 VS Code 打开目录
  3. 用资源管理器打开目录
- 菜单采用 `menu` 语义，可执行项采用 `menuitem` 语义。
- 视觉样式复用现有颜色变量、边框、阴影、悬停和焦点语言，确保 light/dark 主题一致。

## 交互与数据流

1. 用户打开菜单后，焦点移至第一个可用菜单项。
2. 选择“添加会话”时，先关闭选项菜单，再打开现有 `SessionLauncher`。
3. `SessionLauncher` 关闭后，焦点回到触发该流程的项目选项按钮。
4. 选择 VS Code 或资源管理器操作时，先关闭菜单，再调用现有处理函数并打开项目原始目录。
5. 目录操作不得切换活动会话，也不得改变项目展开状态。
6. 打开菜单不会改变当前项目的选中、激活或展开状态。

## 关闭与键盘规则

- 点击菜单外部时关闭菜单。
- 按 `Escape` 时关闭菜单，并将焦点返回当前项目的选项按钮。
- 选择任一可执行菜单项后关闭菜单。
- `ArrowDown` 与 `ArrowUp` 在可用菜单项之间循环移动焦点。
- `Home` 与 `End` 分别移动到首个和末个可用菜单项。
- 键盘导航跳过禁用菜单项。
- 按 `Tab` 或 `Shift+Tab` 离开菜单时关闭菜单，但不阻止浏览器的正常焦点移动。
- 项目被删除或列表变化导致当前菜单所属项目消失时，菜单状态自动清除。

## 禁用与异常行为

- VS Code 不可用时，对应菜单项保持禁用，不能通过鼠标或键盘执行。
- VS Code 禁用项保留现有可访问安装提示，提示内容不因菜单化而改变。
- 打开 VS Code、资源管理器及创建会话仍复用现有调用链和错误处理；本次不吞掉或改写现有错误。
- 菜单关闭逻辑应幂等，连续触发点击外部、失焦或 `Escape` 不应留下残留弹层或错误焦点。

## 测试

### 组件测试

- 每个项目行仅显示“项目选项”按钮，原三个独立按钮不再直接显示。
- 点击按钮可打开、再次点击可关闭菜单；打开另一项目菜单会关闭当前菜单。
- 点击外部、按 `Escape`、按 `Tab` 离开及选择菜单项均按规则关闭菜单。
- 打开菜单后焦点进入首个可用项，方向键、`Home`、`End` 和禁用项跳过行为正确。
- `Escape` 关闭后焦点回到选项按钮；`SessionLauncher` 关闭后焦点也回到对应选项按钮。
- 三个菜单项调用各自现有处理函数且不触发拖拽；VS Code 和资源管理器操作不激活项目、不改变展开状态，“添加会话”保留现有的项目激活行为以显示 `SessionLauncher`。
- VS Code 不可用时菜单项禁用，并保留安装提示和可访问语义。
- 选项按钮正确渲染 `options.svg`，菜单样式使用主题变量。

### 端到端测试

- 原先直接点击三个项目操作按钮的流程改为先打开项目选项菜单，再选择对应菜单项。
- 验证添加会话、打开 VS Code 和打开资源管理器的完整流程。
- 验证菜单操作不会改变活动会话或项目展开状态。
- 验证最小窗口尺寸下选项按钮可见、菜单可操作且不溢出侧边栏可视区域。
- 验证 light/dark 主题下菜单均可见且交互正常。

## 验收标准

- 项目行仅保留一个使用指定 `options.svg` 的选项入口。
- 三个原有操作均可从菜单执行，业务行为与菜单化前一致。
- 菜单在鼠标、键盘、焦点恢复、禁用状态和外部关闭场景下符合本设计。
- 相关组件测试和端到端测试全部通过。
